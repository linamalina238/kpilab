# ADR-0002: Вибір типу ідентифікаторів (UUID)

## Контекст
Потрібно обрати тип ідентифікаторів (id) для всіх сутностей моделі
(User, Category, Product, Order, OrderItem). Це рішення було закладено
ще на етапі первинного spec.md і впливає одразу на всі сутності моделі.

## Розглянуті альтернативи

**Варіант А — auto-increment integer (послідовні числа 1, 2, 3...).**
Просто, компактно, легко читати в логах. Мінуси: за значенням
Order.id можна оцінити загальну кількість замовлень магазину
(наприклад, стороння людина за id=1042 розуміє масштаб продажів);
складно координувати видачу унікальних номерів, якщо в майбутньому
знадобиться кілька серверів бази даних одночасно.

**Варіант Б — UUID.**
Довгий унікальний рядок, що генерується без центрального лічильника.
Мінуси: займає більше місця в базі, менш зручно читати й порівнювати
вручну під час дебагу.

## Рішення
Обрано варіант Б — UUID для всіх первинних і зовнішніх ключів.

## Наслідки
- Ідентифікатори займають більше місця й менш зручні для ручного дебагу.
- Натомість: не розкривається кількість записів стороннім людям, не
  потрібен центральний генератор id, простіше масштабувати систему
  на кілька серверів у майбутньому.
- Усі первинні й зовнішні ключі типізовані однаково — відповідає
  критерію прийняття в spec.md.
